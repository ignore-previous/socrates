# Coordinate long-running work

Use this reference when assigned to coordinate extended or multi-agent execution. Apply the planning skill throughout the work; do not assume that a good opening interview prevents later drift. Use actual available tools and host conventions. Do not claim to schedule, persist, monitor or enforce something the host does not support.

## Agree the operating scope

Establish the approved goal, success evidence, constraints and exclusions. Agree the next executable phase, its completion or review conditions, delegated decisions, relevant spending or time limits, and when to return to the user. Explore material later branches without pretending to know every implementation detail in advance.

Keep an authoritative, durable plan and decision record when the host supports it. Preserve the reasons behind consequential decisions and record what remains open or conditional. Keep it current and accessible to workers. If durable state or restart support is missing, identify that limit before promising unattended continuation across sessions.

## Delegate coherent work

Split work along real dependencies and useful boundaries. Give each worker the intended outcome, relevant decisions and rationale, inputs, expected artifacts, acceptance evidence and discretion. Assign clear ownership for shared changes and identify integration dependencies. Use concurrency where work can proceed independently; do not equate more workers with better delivery.

Read a worker's question or proposal as evidence that may change the plan, not as new user authorisation. Reconcile conflicting findings, goals or changes against the agreed direction. Resolve routine issues within delegation and return material new trade-offs to the user.

## Check progress and adapt

Distinguish reported activity, completed artifacts and verified results. Check the evidence appropriate to the task before accepting completion. Reconcile worker outputs and integration effects; individually successful tasks can still combine into the wrong result.

When an assumption fails or a decision changes, identify affected work, update the record and notify the relevant workers. Hold affected downstream work if continuing would rely on an invalid premise; allow independent authorised work to continue where sensible. Avoid repeated retries or continued resource use without a plausible route to progress and within agreed limits.

At useful milestones or handoffs, preserve what is complete, evidence, decisions, unresolved issues and the next step. Escalate when intent is ambiguous, constraints conflict, a significant premise fails, verification fails persistently or authority is exceeded. Do not ask the user to manage every subtask.

## Respect the host boundary

Socrates provides reasoning, questioning and coordination guidance. The application must implement dependable scheduling, shared state, permissions, budget enforcement, cancellation and recovery where the product promises them. A message board or a prompt alone does not enforce these. Name missing requirements without pretending the skill implements them or guaranteeing an unlimited number of workers.
